## 已实现

1. 本地 BGE-M3：文档与问题使用同一固定模型版本、CLS 池化与归一化，在本机 RTX 4070 上运行，不把资料发送到外部 embedding 服务。
2. 混合检索：保留中文全文、术语别名；按对象融合关键词与向量排名，精确术语保留优先级。可以切换关键词、语义向量、混合三种模式。
3. 精确筛选：材料牌号由明确字段精确筛选；分析类型明确冲突的结果排除，未知分析类型仍标为待确认。默认不检索已停用或冲突对象。
4. 图谱关联：搜索结果读取 Semantica 实际生成的派生图，核对主库版本、哈希、关系依据；可展开关联对象并打开完整记录和已有原件。过期图谱不继续扩展旧关系。
5. 索引续建：对象或正文变化后重算相关条目，旧对象哈希或已变化的片段不会继续作为当前向量证据。模型/编码配置不一致时拒绝混用旧索引。索引事务按批提交，程序关闭后可继续建立。
6. 界面显示索引进度、语义命中渠道、关系依据和候选状态；失败与未命中分别提示。

## 模型与索引边界

模型来自 [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3)，固定提交 `5617a9f61b028005a4858fdac845db406aefb181`。权重 SHA-256 已与上游记录核对：`b5e0ce3470abf5ef3831aa1bd5553b486803e83251590ab7ff35a117cf6aad38`。

采用 1024 维向量。为控制资源使用，当前每个已有片段最多编码前 512 token；超过部分仍保留在全文关键词检索和原件中。没有宣称全文所有字符都进入向量，也没有把卡片拆成不完整的主库记录。向量相似度下限当前为 0.45，属于初始检索设置，尚无完整领域评测证明其最优。

全库目标为 555,413 条：6,978 条完整对象、548,435 条正文片段。交付检查快照完成 42,936 条，随后已增长到 45,384 条；全部完整对象已编码，正文向量化仍在后台继续。以程序当前进度为准，不能把试验库 3/3 就绪解释成真实全库已就绪。保持程序打开可继续建立；关闭后下次在“资料与检索”点击“建立 / 续建语义索引”。

Semantica 仍使用已验证的 0.6.8 打包组件，本轮不是 0.7.0 升级。真实派生图已重建：6,978 个对象、2,391 条关系。派生图服务关联查询，参数权威仍是结构化主库。

## 使用与后续范围

打开原快捷方式，进入“资料与检索”，默认使用混合模式；展开“图谱关联”查看依据。新增/修改对象或关系后，用“更新图谱关联”和“建立 / 续建语义索引”更新派生数据。

未新增 Semantica 实体/关系自动抽取，也未接入问答大模型、完整推理或 CAE Agent 执行。之后如接抽取，应先生成带出处的候选，经过复核再入主库；本次不把自动生成内容当作已确认参数。原有任务包不可执行和工程复核边界保留。

重建 embedding 使用 `build-embedding.ps1` 和 `requirements-embedding-lock.txt`；桌面程序应显式指定独立输出目录，例如 `build.ps1 -DistPath D:\zhishiku\desktop-framework\release-candidate`，不要直接对含业务数据的正式目录运行 PyInstaller。

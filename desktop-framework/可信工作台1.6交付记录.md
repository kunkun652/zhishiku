## Jev 的实际使用

采用可用的直连 TypeSafe API、`jev-1.13.0`，没有使用失效的旧 OpenRouter 模型别名。

- `jev-triage`：分类需求的体验、权限、引用、增量问题。
- `jev-route`：依据能力把跨组件实现交给 Codex，把有限选项判断交给 Jev。
- `jev-code-review`：对指定源码、差异及测试回执进行权限、外发、发布和验证覆盖审查。
- `jev`：8 项小样本先核对，再做限定大小/超时/次数的后续调用；检查点判断明确拒绝“所有层面都已生产验证”的过度声明。
- 8 项小样本与预期一致，包括应交人工的未知项；这只是 pilot，不是一般准确率证明。部分调用曾遇到 HTTP 529，已保留结果并限定重试。审查提示验证覆盖需人工核对，因此继续完成源码/打包/桌面/数据保全检查。
- 只发送代码、合成案例与测试回执；未发送业务资料或密钥。Jev 给建议，不签发权限、不作工程批准。本版没有把 Jev 暗中接为业务资料自动外发服务。

## 尚未宣称完成的部分

- 真实问答服务尚未填写和联测；需用户在工作台设置自己的 URL/model/Key。知识抽取运行时也未配置模型，工作台的问答 Key 不会自动用于抽取全文。
- 多人/项目级 ACL 尚未实现；现有边界不抵御同一 Windows 账户下的恶意程序。
- 增量构建仍扫描源记录，图谱仍可能整体重建；不是每个环节都实现 O(变更量) 更新，也不是跨 SQLite/文件系统的分布式原子事务。源版本校验和拒绝陈旧引用继续保留。
- 原有新向量索引 776974 单元已就绪，但本次升级不主动更改当前索引选择，不把“构建完成”说成“已切换”。
- 模型支持性核对只是辅助检查，不能替代工程复核或保证结论正确。

## 已实现

- 中文工作台，资料检索、四类卡片、模型、案例、图谱、流程与能力、任务包、运行验证、导入质量十个入口。
- 16种空白模板：材料、术语、网格策略、工况、资料、模型、案例、流程、Skill、Tool、验证基准、失败经验、任务、运行、缺口、训练/评测登记。
- 表单新建/编辑、单条模板JSON导入、完整JSON导出、版本历史、并发修改检测、内容哈希。模板在 templates 文件夹也可直接填写。
- 中文字面全文和术语别名扩展，分析类型硬筛选，未知适用条件单独标记；未命中与服务异常分开。
- 有依据的关系创建，图谱拖动缩放、类型筛选、对象定位、一/两跳查询、对象详情；关系端点版本变化后标记失效。
- Semantica 0.6.8 GraphBuilder 实际独立运行；“Semantica 重建”从结构化主库产生 graph-derived.json。图谱不作为另一份参数权威库，没有启用自动实体抽取、LLM推理或向量检索。
- 原件手动附加后复制到受管目录，SHA-256校验和同对象重复上传去重。STEP/IGES/BREP查看器沿用OCCT；BDF支持壳/线单元，STL/OBJ支持表面。实体网格与OP2结果场解析尚未接入。
- 任务包冻结完整对象及版本、文件哈希、关系和缺口；目前所有任务包都为 executable=false，未开放工程复核晋级和执行授权。
- 运行、失败、案例、训练/评测信息可登记为候选。候选回流不会自动成为已验证知识。
- ZIP备份与恢复校验。恢复到新目录，当前空间不覆盖。

## 第一次使用

1. 知识卡片 → 使用模板 → 填写名称与已知字段 → 保存。未知留空。
2. 模型资产 → 使用模板 → 保存 → 查看 → 附加原件 → 预览。
3. 案例登记目标、模型、卡片、步骤、BDF/F06/OP2与显示证据；未具备的证据留空。
4. 知识图谱 → 建立关系，填写真实依据；有内容后点 Semantica 重建。
5. 任务知识包 → 选择对象 → 检查缺口并导出。

材料参数 JSON 采用 `[{"name":"参数名","value":null,"unit":"","source":""}]`。未知数值用 null。材料仅允许 MAT1/MAT8 类型，不在材料卡中存 PSHELL/PCOMP、厚度或铺层。

模型区域映射 JSON 每项包含 semantic_name、geometry_version、mesh_version、faces、nodes、elements、source。区域映射属于登记契约，当前不会自动测量CAD或将语义施加到网格。

## 数据与恢复

默认数据库：程序目录下 `data\knowledge.sqlite3`；原件：`data\assets`；运行端点：`data\runtime.json`。数据空间独立于 EXE。复制/备份要包含 data 和受管原件。

界面可将ZIP恢复到 `restored-spaces\<唯一编号>` 并校验数据库与文件哈希。验证通过后，关闭程序，使用启动环境变量 `ZH_DATA_ROOT` 指向恢复目录即可切换；也可保留原data，将恢复目录复制为另一个程序副本的data。不要在程序运行时覆盖数据库。

## 当前边界

这是一套可运行的知识框架，不是完整CAE执行器。未导入真实语料、未切片、未配置embedding/大模型、未连接智能体、未执行求解、未进行工程或适航批准。自动测试数据全部位于 evidence 下独立空间。正式 data 业务对象为0。

参照 PDF 的未来执行控制、结果物理验证、正式人员复核、训练集冻结和独立评测，只提供登记字段与接口边界，尚未实现自动流程。STEP/IGES/BREP组件保留且资源完整，本轮真实显示测试为合成BDF三角形；未使用用户原模型进行CAD验收。

## 开发与重建

源码在 src，测试在 tests。build.ps1 使用原平台Python环境只读打包，不安装或修改原环境；正式程序已包含Python与依赖，无需该环境。Semantica使用独立Python 3.12组件，build-semantic.ps1 为重建命令。重建顺序为 Semantica、桌面程序。许可证随程序保存。

统一接口详见 `接口与架构映射.md`；测试证据见 evidence。本版本请从正式 EXE 或专用快捷方式启动。
